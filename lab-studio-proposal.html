CAI 3801 Lab Studio

A complete read of the Canvas course (modules, assignments, quizzes, files, tools, and the project that runs through them), followed by a design for one in-Canvas workspace where students open a lab and find the guidance, the tools, the checks and the submission in one place.

Yes, it can be built. One limit shapes the whole design.

Everything browser-based in this course can live inside one Canvas-launched app: the AI simulation lab, LLM calls, guided steps, answer sheets, evidence capture, auto-checking and grade return. Tableau Desktop and the Make.com editor cannot be put inside a web page. The studio wraps around them: it guides each step, receives what students build (the .twbx file, Make run logs), checks it automatically against an answer key computed from the course dataset, and files the submission in SpeedGrader.

Things I noticed that the studio should fix

Canvas assignment groups are all weighted 0%, while the deck says 40/40/10/10. Students' Canvas grade totals will not match the syllabus until the weights are set.

No rubrics are attached in Canvas. They exist only as text inside the descriptions and Word files, so SpeedGrader cannot score against them. For 394 students, that means a lot of manual grading.

Grading the Tableau labs is mostly mechanical. Sheet names, calculated-field formulas, parameter ranges, filter targets and dashboard actions are all stored in the .twbx and can be checked by software. Student answers can be compared to an answer key computed from the CSV.

The sample AI report ("Report 1") says Office Supplies sales are "N/A". The data has $719,047. The bug came from the crosstab handed to Make. It is a ready-made teaching case for the "check before you automate" rule.

Files are duplicated or drifting. There are two Lab_Assignment_YourName versions and two copies of the guardrail template, one module links the same doc twice, a Week 1 slide still says "ISM 4212", and some quiz dates differ from their assignment due dates (probably section overrides).

Tableau's forecast values (exponential smoothing, MASE) and k-means clusters are not stored in the .twbx, so those answers are checked against the instructor's per-state key with a tolerance rather than recomputed.

What the .twbx checker can verify

A .twbx is a zip holding the workbook XML and the data extract. The studio can read:

  • Exact sheet names ("Category and Sub-Category", "Location Map", "Forecast", "What-If" and so on), and that the Sales KPI sheet is still present.
  • Calculated fields and their formulas: CY Profit, PY Profit, Profit Change %, List Price, Adjusted Sales, Adjusted Profit.
  • The Discount Cap parameter: float type, range 0 to 0.8, step 0.05, % format.
  • The State filter value against the student's assigned state (wrong state is graded out of 50), and the Tables sub-category filter.
  • Reference-line constant equal to the state's target; the forecast is on; a diverging palette centered at 0.
  • Dashboard size 1600×900, the container tree, filter-action source and targets (Map → Segments and What-If only), and the saved opening state (2017, the recommended cap).

What each lab looks like inside the studio

Lab 1 · AI judgment

The sim lab runs natively. Predict is locked until the student commits an answer, and Run goes through the proxy. Field Notes are required before moving on. The Portfolio is generated and submitted automatically.

Tableau + Make practice

A step rail paired with video clips. The student's Make scenario posts its run to the studio, which compares the report's numbers to the chart and flags mismatches like the "N/A" bug.

Descriptive / Diagnostic

The Word sheet becomes in-app fields. Uploading the workbook triggers structural checks, and numbers are checked against the key. Captions are checked for a number, a comparison and an implication. The AI-use box keeps its before and after versions.

Predictive / Prescriptive

The state is assigned automatically from the roster's last name. The scenario table is prefilled with 7 caps to fill in, and the uplift arithmetic (gain ÷ 48 vs target) is checked step by step.

Dashboard + video

The wireframe is drawn in the studio, and its layout is compared to the dashboard's containers. The "test that catches most mistakes" runs automatically from the action targets. The video link is checked for public access.

Agentic guardrail → final project

The Policy sheet is generated from the student's own Lab 2 caps. Make runs post to an approval log in the studio, where the student approves or rejects as the named human. Test cases (normal, edge, adversarial, refusal) are scored, which is the evidence the final project asks for.

What has to be true before it ships

Canvas admin approval

Your TA role cannot add LTI tools. That permission is off, and LTI 1.3 developer keys are created at the USF account level. The professor needs to request it from USF IT / Canvas admins, which usually involves a security and accessibility review.

Student data (FERPA)

Grades and submissions are education records. Host on infrastructure USF approves (USF runs on Microsoft, so Azure is the easiest fit), keep only what the labs need, and never send names to the LLM. That last point matches the course's own data rule.

Accessibility

Public universities now have to meet WCAG 2.1 AA for web content under the ADA Title II rule. Build that in from the first screen; captioned videos and keyboard-usable steps are the main items.

Cost at 394 students

Gemini's free tier per student (bring your own key) costs nothing. A single course key needs a budget and rate limits. Hosting a small app and database is low-cost on student-scale traffic.

Build plan

Phase 0
2–3 weeks
no admin needed

Standalone studio, one lab. Build it the way the sim lab is deployed today: students open a link and upload the generated PDF/DOCX to Canvas themselves. Pilot it on the Agentic Guardrail lab (current module) or the Predictive/Prescriptive lab, with the answer-key engine and .twbx checker. This proves the idea to the professor and to IT.

Phase 1
3–4 weeks

LTI 1.3 launch and grade return. Single sign-on from the assignment, roster-based state assignment, files and scores into SpeedGrader. The instructor dashboard shows who is stuck at which step.

Phase 2
4–6 weeks

All labs moved in. Port the sim lab, the Make run webhook and evidence log, the wireframe editor, and the final-project evaluation harness with its test cases.

Phase 3
pilot

Tableau in the browser. If Tableau's academic program grants a Tableau Cloud site, embed web authoring so Chromebook and iPad students can do every lab.

Suggested stack: Next.js + TypeScript, Postgres, an LTI 1.3 library (for example ltijs), blob storage for uploads, a small server function for the LLM proxy, and JSZip plus an XML parser for .twbx files. All of it can be built and run without paid licences.

Questions to take to the professor

  • Should the first version be standalone (fast, no IT review) or wait for LTI?
  • Which lab to pilot first: the current Agentic Guardrail, or rebuilding a finished one (Predictive/Prescriptive) where the answer keys already exist?
  • Is the goal to keep Tableau Desktop, or would he use Tableau Cloud in the browser if USF can get it?
  • One course-paid LLM key, or keep students on their own Gemini keys?
  • Should auto-checks give students feedback before the deadline (formative), or only pre-score for the grader?
